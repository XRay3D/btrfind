# btrfind — мгновенный поиск файлов на btrfs

Аналог Everything для Linux с btrfs. Демон держит в памяти индекс имён всех файлов и обновляет его на лету. Графический интерфейс находит файлы по мере ввода: 1–30 мс на 2,4 млн файлов.

| Everything / NTFS | btrfind / btrfs |
|---|---|
| Чтение MFT | Чтение B-дерева подтома через `BTRFS_IOC_TREE_SEARCH_V2` (12 потоков) |
| USN-журнал, живые изменения | `fanotify` с `FAN_MARK_FILESYSTEM` на всю ФС, одна метка на все подтома |
| USN-журнал, догон после выключения | Номера транзакций btrfs: поиск по дереву с `min_transid` (миллисекунды) |
| Everything Service | systemd-сервис `btrfindd` (root), GUI работает от пользователя |
| «Search Everything…» в Проводнике | «Искать здесь (btrfind)…» в контекстном меню папок Dolphin |

## Установка

```sh
./install.sh            # проверка зависимостей, сборка, тесты, установка, запуск сервиса
./install.sh status     # состояние сервиса и томов
./install.sh uninstall  # удалить (--purge — вместе с сохранёнными индексами)
```

Другие режимы: `./install.sh build` (только сборка), `./install.sh install` (установить собранное). Опции: `--prefix DIR`, `--debug`, `--no-service`, `--skip-tests`.

Зависимости (ALT Linux): `cmake gcc-c++ pkgconf qt6-base-devel libpcre2-devel glibc-kernheaders libgomp-devel`; необязательно `kf6-kio-devel` — эскизы видео, PDF и документов.
Ядро: ≥ 5.17 для живых обновлений и ≥ 6.8 для fanotify на подтомах btrfs.

Что устанавливается:

| Файл | Назначение |
|---|---|
| `/usr/sbin/btrfindd` + `btrfindd.service` | демон индексации (root), индексы в `/var/lib/btrfind` (0600) |
| `/usr/bin/btrfind` | GUI и консольный клиент |
| `/usr/share/applications/btrfind.desktop` | ярлык в меню приложений |
| `/usr/share/kio/servicemenus/btrfind-servicemenu.desktop` | пункт «Искать здесь (btrfind)…» в контекстном меню папок Dolphin |
| `/usr/bin/btrfs-poc` | диагностика (замеры скана, догона, fanotify) |

## Использование

GUI: `btrfind` из меню приложений или в терминале. `btrfind --in ~/Документы` ищет только в папке. Повторный запуск не открывает второе окно: запрос и папка передаются уже открытому.

| Клавиши | Действие |
|---|---|
| ввод текста | поиск по мере набора |
| ↓ / Enter в строке поиска | перейти к результатам |
| Enter / двойной щелчок | открыть |
| Ctrl+Enter | показать в папке (Dolphin выделит файл) |
| Ctrl+C / Ctrl+Shift+C | копировать файлы / полные пути |
| Esc | очистить запрос |
| Ctrl+F, F5 | к строке поиска, обновить |
| Ctrl+колесо, Ctrl+1…6 | таблица ↔ плитка эскизов разного размера |
| Ctrl+H, Alt+↓ | история поиска |
| F2, Ctrl+Z | переименовать, отменить переименование |

Результаты можно перетащить в другое приложение. По щелчку правой кнопкой есть пункт «Искать в этой папке».

**Столбцы.** Щелчок правой кнопкой по заголовку таблицы (или «Вид → Столбцы») включает и выключает столбцы:
Имя, Путь, Размер, Изменён, Создан, Расширение, Тип, Владелец, Группа, Права, Открыт, На диске, Полный путь.
Сортировка выполняется демоном по всем столбцам, кроме «Открыт» и «На диске»: их значения читаются с диска только для видимых строк.

**Эскизы.** **Ctrl+колесо мыши** переключает таблицу в плитку эскизов и меняет её размер (64 → 96 → 128 → 192 → 256 px); прокрутка в обратную сторону возвращает к таблице. То же самое — «Вид» и **Ctrl+1…Ctrl+6**. Порядок в плитке такой же, как в таблице («Вид → Сортировка»), выделение общее. Эскизы строит KDE KIO, как в Dolphin (видео, PDF, книги, шрифты…), с общим кэшем `~/.cache/thumbnails`; без KIO — только изображения.

**Строка состояния** показывает число найденных объектов и их общий размер, а при выделении — сколько выделено и сколько это занимает. Размер считает демон, поэтому он точен даже для Ctrl+A на миллионе строк. Размер папок в сумму не входит.

**История поиска.** Запрос запоминается при Enter, при любом действии с результатом (открыть, показать в папке, копировать, переименовать) и через 3 секунды после окончания ввода, если что-то найдено. Список открывается кнопкой с часами в строке поиска, **Ctrl+H** или **Alt+↓**. В меню «Поиск» историю можно очистить или отключить.

Консоль:
```sh
btrfind --cli main.cpp                    # первые 50 результатов
btrfind --cli -n 0 -l "ext:pdf size:>10mb" # все, с размером и датой
btrfind --cli --sort size --desc --regex '\.(mkv|mp4)$'
btrfind --status
```

## Переименование

Как «Multi-file Rename» в Everything: выделите результаты и нажмите **F2** (или «Переименовать…» в контекстном меню).

- **Один файл:** окно с новым именем; имя без расширения уже выделено.
- **Несколько файлов:** диалог с *старым* и *новым форматом*. Старый формат подбирается сам: общая часть имён плюс `%1` на месте различий (`IMG_0001.jpg`, `IMG_0002.jpg` → `IMG_%1.jpg`).

| В новом формате | Значение |
|---|---|
| `%1`…`%9` | части имени, совпавшие с `%1`…`%9` старого формата |
| `%n`, `%03n` | порядковый номер в порядке строк таблицы; `001`, `002`… |
| `%%` | знак процента |
| `\1`, `$1` | группы, если включено «Регулярное выражение» (старый формат — PCRE на всё имя) |

Примеры: `IMG_%1.jpg` → `Отпуск_%1.jpg`; `%1 - %2.mp3` → `%2 - %1.mp3`; `%1.%2` → `фото_%03n.%2`;
regex `(\d{4})-(\d\d)-(\d\d)_(.*)` → `\3.\2.\1 \4`.

Предпросмотр показывает каждое новое имя и проблемы: повтор нового имени, занятое имя, `/` в имени, длина больше 255 байт. Пока есть ошибки, переименовать нельзя.

Переименование выполняет сам GUI от имени пользователя, а не демон под root: чужие файлы через btrfind переименовать нельзя. Существующие файлы никогда не перезаписываются. Обмен имён (`a↔b`) и цепочки проходят через временные имена. Если в выделении есть и каталог, и файлы внутри него, сначала переименовываются файлы. **Ctrl+Z** отменяет последнее переименование.

## Синтаксис запроса

| Запрос | Что найдёт |
|---|---|
| `отчёт 2026` | имя содержит оба слова (без учёта регистра, включая кириллицу) |
| `"мой отчёт"` | фразу с пробелом |
| `pdf \| djvu` | любое из слов |
| `report !draft` | исключить слово |
| `*.pdf`, `IMG_????.jpg` | маска на всё имя |
| `src/main`, `path:proj` | по полному пути |
| `regex:^CMake.*\.txt$` | регулярное выражение PCRE2 (JIT); кнопка `.*` — весь запрос как regex |
| `file:` `folder:` | только файлы или только папки |
| `ext:pdf;docx` | по расширению |
| `size:>10mb`, `size:1kb..5mb`, `size:empty / tiny / small / medium / large / huge / gigantic` | по размеру |
| `dm:today`, `dm:yesterday`, `dm:thisweek`, `dm:last7days`, `dm:2026-01-01`, `dm:>2026-01-01`, `dm:2026-01-01..2026-02-01` | по дате изменения |
| `dc:…` (те же формы) | по дате создания |
| `owner:имя`, `group:имя` (или числовой id) | по владельцу и группе |

Кнопки `Aa` и `/` включают учёт регистра и поиск по полному пути. Список «Документы / Изображения / …» добавляет готовый фильтр расширений.

## Как это работает

```
src/core/    индекс (изменяемый, пулы имён), скан ioctl/обходом, сверка с ФС, запросы, поиск, хранилище, протокол
src/daemon/  btrfindd: тома, очередь задач, fanotify, сервер (unix-сокет, CBOR)
src/gui/     btrfind: окно на Qt6 Widgets, модель с подгрузкой страниц, консольный режим
src/poc/     btrfs-poc — диагностика
tests/       юнит-тесты ядра (QtTest)
```

- **Тома.** Индексируются все смонтированные подтома btrfs и вложенные в них. Содержимое под чужими точками монтирования скрывается.
- **Запуск.** Сохранённый индекс загружается (≈0,2 с на 1,8 млн файлов), затем выполняется догон с сохранённого generation. Полное сканирование нужно только при первом запуске (≈3 с на 1,8 млн файлов).
- **Живые изменения.** fanotify ставит метку через невидимое монтирование верхнего подтома (`subvolid=5`). Каждое событие сверяется с реальной ФС (`statx`), поэтому обработка идемпотентна и не зависит от порядка событий. Переименованный каталог сохраняет поддерево. При переполнении очереди запускается догон.
- **Права.** Демон определяет пользователя через `SO_PEERCRED` и показывает ему только то, что он может увидеть сам: `r+x` у родителя и `x` у всех предков. ACL пока не учитываются.
- **Поиск.** Префильтр `memmem` по пулу имён в свёрнутом регистре, затем проверка остальных условий, всё параллельно (OpenMP). Сортировка выполняется на стороне демона, GUI подгружает только видимые строки.

## Ограничения прототипа

- Другие ФС (ext4, xfs и т.д.) не индексируются. Задел есть: обход каталогов уже реализован (`walk_scan`), догон для них — это полный пересмотр.
- ACL не учитываются при проверке прав.
- Без root демон работает обходом каталогов, без живых обновлений и без догона. Так удобно для разработки: `btrfindd --socket $XDG_RUNTIME_DIR/b.sock --state-dir /tmp/b`.
- Память — около 130 байт на файл (≈240 МБ на 1,8 млн).
